# Plants 详情页重构方案

更新：2026-11-04
状态：Living Field Overview 已进入实现并以本地样例数据完成首版；Devices 与 Site details 仍待后续规划。

## 1. 本轮范围

- 先重构 `/plants/:id` 的 Overview，不实现 Device 与 Plant Info 的完整重做。
- 产品首个可落地场景以单个逆变器电站为基线，再兼容电池、加热器和多设备电站。
- 保持已有路由、业务事实和权限边界，不在设计中虚构远程控制、云端实时性、写入权限或后端能力。
- Overview 中的纯展示信息不得伪装成按钮；可进入下级、切换作用域或执行动作的内容必须有明确的文字、箭头或按钮。

## 2. 线上功能盘点

### Overview

- 电站级信息：收藏、地图位置、运行状态、通信状态、本地时间、天气与未来几天预报。
- 设备级信息：设备选择、默认/诊断视图、实时能量流、设备运行状态与模式。
- 能量流节点：PV、Battery、Grid、On-grid、Backup，并带实时功率与部分累计能量。
- 历史数据：可切换逆变器、电池、电池 Cell、加热器；可切换 Tags、设备/数据标签与日期。
- 今日统计：购电、售电、电池充放、光伏发电、家庭用电、节省金额、能源来源占比、当前状态。
- 运维信息：System Log、Fault & Warning、Service Ticket；均可在卡片内预览或展开。

### Device

- 查看电站内设备清单。
- 查看设备型号、固件、硬件版本、SN、Check Code、装机容量和电池 Cluster。
- 添加设备、升级设备、进入设置、更多操作、展开电池 Cluster。

### Plant Info

- 基础信息、电价、Owner、Installer Contact、Plant Picture、Visitor Management。
- 编辑基础信息、添加图片、添加 Owner、邀请 Visitor。

本轮只把这些功能作为 Overview 的上下文和下钻目标，不重做其具体表单。

## 3. 当前主要问题

1. **作用域不明确**：Overview 默认进入 `iHybrid`，但页面标题是电站详情；顶部设备选择与图表内设备标签重复，用户无法判断当前看到的是电站数据还是单台设备数据。
2. **联动不完整**：切换顶部设备后，主视觉和统计发生变化，但图表仍保留所有设备标签，部分页面形成大面积空白。
3. **视觉中心不集中**：能量流、地图天气、图表、统计、日志、告警和工单占据相近权重，首屏没有明确阅读顺序。
4. **能量流可读性不足**：细线连接、分散数值卡与写实设备图混在一起；重要功率和流向不够突出，节点关系也不够直观。
5. **交互路径不明确**：展开、添加、设置、诊断、设备切换使用相似的小图标；纯展示卡片与可点击卡片缺少状态差异。
6. **重复信息较多**：实时能量流与 Current State 重复，地图天气面积过大，图表、统计区又分别承担设备选择。
7. **空态与离线态不完整**：加热器等设备离线或缺少数据时，只剩大面积空白，没有解释缺失原因或下一步入口。

## 4. 设计基准

- 不按竞品页面临摹。竞品只用于确认“能量流需要成为视觉中心”“设备与数据层级需要稳定”等通用问题。
- 设计只从 WattDesk 当前已有元素出发：顶部导航、工作区页头、Overview / Devices / Site details、设备切换、iHybrid / iStorage / iHeater 设备形象、PV / Battery / Grid / Home 节点、今日统计、趋势图、告警、日志、Service Ticket、站点与天气信息。
- 保留当前深浅主题、SF Pro 字体、中性色、玻璃控件、设备状态色和能量语义色，不引入新的品牌语言或外部页面结构。
- 当前 `Overview` 是卡片网格；本轮必须改变其组织方式，不再以重复的独立卡片作为页面主体。

## 5. 设计方向

本轮比较两个沉浸式方向，当前已选择 **Living Field**：

- **Living Field / 连续能量场**：把整页作为一张连续空间，设备、能量线、关键数字和趋势直接悬浮在场景中。
- **Control Room / 单画布控制台**：作为备选研究，保留当前横向能量关系，用左侧设备轨、中央拓扑、右侧事件上下文和底部趋势层构成一个完整控制台，不拆成卡片。

### 核心原则

- **先看当前，再看历史**：首屏先回答“现在发生了什么”，第二屏回答“今天表现如何”。
- **直接进入设备，再回到电站上下文**：进入 Overview 后直接选中设备列表中的第一台设备；电站级状态、天气、位置和工单仍作为不随设备变化的上下文出现。
- **一个设备作用域控制联动模块**：全页只保留一套 active device；所有设备级模块读取同一状态，不再各自维护设备选择。
- **一个连续画布**：能量流、状态、统计和趋势共享同一背景与视觉场；不以卡片边界分割内容。
- **一个视觉中心**：能量流与当前设备是唯一主视觉，其他信息围绕它服务。
- **静态与动作可见区分**：纯指标不响应点击；可下钻内容有箭头或 `View details`；操作使用具名按钮。
- **颜色只表达数据**：界面本身保持中性，Solar、Grid、Battery、Home 使用固定语义色。

### 6.1 页面头

- `Overview / Devices / Site details` 移至顶部全局导航下方，单独占一行，不再与面包屑挤在同一行。
- 下一行只保留面包屑与电站名；电站名后紧邻收藏按钮，收藏状态与 Plants 列表一致。
- 数据新鲜度 `Live / Updated N min ago` 放在页面标签行右侧，不再占用面包屑行。
- 顶部横向上下文条右侧与 Operations rail 对齐，左侧从设备轨之后开始，整体宽度收窄并匹配下方能量流画布，不横跨设备切换区。
- 其余低频操作放入 `More`：诊断、设备设置、导出等，不把齿轮、上传和展开图标散落到各卡片。

### 6.2 全页作用域

- 不再提供 `Whole plant` 聚合视角；Overview 的监控内容始终属于一台当前设备。
- 进入页面时默认选择设备列表中的第一台设备；设备顺序由 Devices 页面的自定义排序决定。
- 只有一台设备时不显示设备切换轨；两台及以上才显示。当前设备身份由能量场中心和页面数据本身表达，不再额外显示顶部 `Current device` 标签。
- 设备切换轨与顶部上下文条同轴起始，从画布左上角向上排列，不占用能量流中心区域。
- 设备项同时显示类型、在线状态和数量；多台同类设备先显示汇总，再在二级菜单选具体设备。
- 首次进入只含一个逆变器的电站时直接显示 `iHybrid`，不需要额外选择层级。
- 当前设备写入 URL 查询参数，例如 `?device=<deviceId>`；刷新、复制链接和标签恢复后仍回到同一设备。没有参数时才读取 Devices 的排序并选中第一台。
- 模块内不再出现第二套设备切换器。图表只展示当前 scope 可用的指标系列。

### 6.3 作用域矩阵

| 模块 | 当前设备 | 电站固定上下文 | 说明 |
|---|---|---|---|
| Energy flow | 突出当前设备，其他节点保留为上游/下游上下文 | — | 切换设备时节点位置不变 |
| KPI strip | 当前设备相关指标与电站贡献/占比 | — | 标题标注数值口径 |
| Energy trend | 当前设备可测指标 | — | 指标型而非设备型切换 |
| Device status | 当前设备置顶并高亮 | 全部设备摘要入口 | 排序在 Devices 页面维护 |
| Alerts & activity | 自动按当前设备过滤 | 可切换到全站告警与事件 | 过滤器状态清晰 |
| Service tickets | 与当前设备有关的工单 | 电站全部相关工单 | 无关联数据时明确提示 |
| Plant pulse | — | 运行状态、通信、天气、位置、本地时间 | 用 `Plant` 标签说明不随设备改变 |

## 7. Overview 模块职责

### Energy flow

- 全页唯一主视觉，直接占用连续画布的主要面积，不与天气、告警和图表平均分栏。
- 当前实现阶段保留 `Energy flow` 标题与容器，但内部设备、PV / Battery / Grid / Home 节点、连线、读数和圆环全部暂时移除；后续按确认稿重新接入，不从旧实现恢复。
- 后续重新设计时再接入中心设备与 `PV / Battery / Grid / Home` 节点；`On-grid` 与 `Backup` 作为 Grid 的下级读数，不再各占一张浮卡。
- 后续当前功率使用大号等宽数字；今日累计、SOC、温度等作为次级信息。
- 后续流线宽度与亮度和功率占额定功率的比例相关；方向用低强度移动光点表示，减少动态效果时变为静态箭头。
- 后续节点读数直接附着在能量场中，不使用带边框和独立底色的数据卡。
- 后续点击节点切换到对应设备作用域；点击设备主体进入设备详情。两种动作分别提供 hover 高亮与 tooltip。
- `Diagnostic` 继续保持不进入主流程，仅排查时使用。

### Plant pulse

- 合并当前地图、天气与运行状态的摘要价值，不再让地图与天气平分首屏。
- 采用 Control Room 已验证的横向上下文条：运行状态、通信、天气、地点和时间在同一条顶部信息线上。
- 地图缩略图只作为位置识别，完整位置和天气进入 Site details。
- 该模块始终为电站级，不随设备作用域切换。
- 视觉上作为画布边缘的上下文信息，不单独形成白卡或玻璃卡。

### Today at a glance

- 采用一条无卡片边界的 4–5 项 KPI 基线，只用分隔线、对齐和数值层级组织。
- 推荐首版：Solar generated、Home used、Self-powered、Grid balance、Savings；数值由当前设备参与范围生成。
- 有昨日/周期对比时显示变化；没有真实对比时不显示伪造箭头或百分比。
- 逆变器首版使用独立的 `Statistics` 天视图面板：默认 `Today`，包含 Energy、Savings、Self-powered、Current state 四组；电池与加热器后续补充各自指标口径。
- 天视图内部以竖向分隔线组织模块，不使用四张独立卡片；日期切换在首版只保留 Today 的静态状态，Day / Month / Year / Total 的完整选择后续实现。

### Energy trend

- 顶部只保留三类控制：指标模式、时间范围、系列开关。
- 图表不再重复设备页签；系列由当前 scope 决定。
- 当前设备显示对应可测指标；逆变器默认显示生产、消费、电池、电网，可切换为能量或功率。
- 无数据时显示原因、最后上报时间与相关设备入口。
- Hover tooltip 使用共享浮层；触屏点击数据点保持同一内容。
- 图表可以作为画布底部的地平线数据层，不包在独立大卡片中。

### Device rail

- 展示设备类型、名称、连接状态和运行状态；顺序由 Devices 自定义。
- 点击设备项切换当前作用域；`Manage devices` 进入 Devices。
- 离线设备仍保留在列表中，以低饱和状态显示并明确最后在线时间。
- 桌面可使用左侧窄轨或页头下方的连续分段；在单画布方案中不得退化为多张设备卡。

### Context rail

- 右侧保留一条连续的 Operations rail，但必须明确分成 `Fault & Warning`、`System Log`、`Service Tickets` 三个部分，不可合并成一个含义模糊的 Signals 列表。
- `Fault & Warning` 位于最高优先级，直接展示当前最重要或最近 2 条告警及错误码，不能只显示数量。
- `System Log` 使用深色终端表面、等宽字体、时间 / 设备 / 事件分列，形成明确的工程师工具感。
- `Service Tickets` 直接展示近期票号、标题和状态，保留进入完整列表的入口。
- 点击任一部分的标题或 `View all` 后，从右侧展开共享 Glass Surface 的详情浮层，内部按原类型保留 `Fault & Warning / System events / Tickets` 分页。
- 告警优先于普通上下线日志；同一故障的 start/stop 在一行内表达持续时间，减少重复记录。
- 无异常时展示清晰且克制的正常状态，不显示空的月份折叠器。

### Service tickets

- 在 Context rail 中保留近期工单，展示状态、标题、设备/电站关联、最后活动时间。
- `New ticket` 与 `View all` 使用明确文字动作，不使用裸加号。

## 8. 视觉语言

- **画布**：沿用当前浅色 `#EDEDED / #F7F7F7` 与深色中性体系，但把页面变成一个连续画布；玻璃只用于设备轨、悬浮控件和上下文浮层。
- **层级**：不通过卡片描边和底色区分模块，改用空间位置、留白、分隔线、数值尺度和能量线建立层级，彻底减少“每一块都是独立白卡”的碎片感。
- **硬件图**：保留真实设备渲染，但降低背景阴影，放大主体，避免当前小型设备卡悬在空白中的观感。
- **数字**：核心实时值 32–44px、tabular numerals；标签 12–13px；单位和口径不混入大数字。
- **状态色**：Normal 绿、Attention 琥珀、Fault 红、Offline 中性灰；不能只靠颜色，必须同时有图标与文字。
- **能量色**：PV 暖黄、Grid 绿、Battery 蓝紫、Home 青蓝；同一能量类型在所有图表、节点和图例中保持同色。
- **表面关系**：不把地图天气、统计、图表、告警和工单做成同权重卡片；它们以边缘读数、基线、地平线图表和上下文轨进入同一画布。
- **动效**：scope 切换采用内容淡变和数值插值；能量流只让真实流动方向产生移动效果；减少动态效果时全部静止。
- **深度**：Living Field 使用中心能量核、轨道和环境光；Control Room 使用透视网格、横向能量路径和底部趋势层。两版都不能退化为卡片拼贴。

## 9. 交互与状态规则

### 路径清晰

- 纯展示数值：无 hover 底色、无指针、无按钮语义。
- 可下钻内容：模块标题或行尾显示箭头，并提供 `View details` / `View all`。
- 可切换内容：使用分段控件或清晰的下拉，不使用无标签图标。
- 设置类操作：使用 `Settings`、`Upgrade`、`Edit` 等具名字样，危险操作不得与普通设置并排。
- 展开：只用于图表、完整告警和日志；图标带 `Expand` tooltip，不与进入详情共用。

### 默认、加载与异常

- 能量流、统计、告警和趋势分别加载；能量流不等待日志和工单接口，也不因次级数据加载而遮住整个画布。
- 数值过期时显示 `Updated N min ago`；超过数据有效性阈值时转为 Attention 状态。
- 设备离线保留节点布局，数值显示 `—`，提供最后在线时间和 `View device`。
- 设备不存在时从拓扑中去掉对应节点，能量流自动重排，不留下空位。
- 图表无数据时保留筛选条件，显示可操作的空态，不显示大面积空白画布。
- 告警为零时显示简短正常状态；工单为零时显示 `Create ticket`。

## 10. 响应式

- `≥1280px`：设备轨、能量场、上下文轨和底部趋势层共用一个连续画布。
- `768–1279px`：设备轨保留在画布上部，Plant pulse 与 Context rail 收为边缘读数，能量场仍是主视觉。
- `<768px`：设备轨改为横向滚动但固定当前项可见；能量流改为纵向拓扑；KPI 两列；所有操作入口常驻，不依赖 hover。
- 页面不得产生整页横向滚动；图表内部允许横向滚动时必须提供滚动反馈和固定轴标签。

## 11. 逆变器优先的 MVP

首版设计先保证单逆变器、单电池、单加热器均可通过同一模型渲染：

1. 进入页面直接显示设备列表第一项；只有一台逆变器时，拓扑为 PV → Inverter → Home，并保留 Grid 分支，隐藏不存在的 Battery。
2. 增加电池或加热器后，自动出现在设备顺序中，不改变整体布局；用户可在 Devices 页面拖拽调整顺序。
3. 首版重点完成逆变器作用域；电池和加热器使用同一节点契约，后续补充各自专属指标。
4. 所有设备只在 Device 页面执行升级、设置、删除等操作；Overview 的设备节点只负责监控、切换与进入详情。

## 12. 建议的共享组件

| 组件 | 用途 | 约束 |
|---|---|---|
| `ScopeSwitcher` | 当前设备作用域 | 单一 active device，顺序来自 Devices，支持键盘与 URL 同步 |
| `EnergyNode` | 能量流端点 | 直接落在画布中，统一标签、值、单位、状态与可点击语义 |
| `KpiBaseline` | 今日指标带 | 无卡片边界，统一数值、单位、比较和空态 |
| `ChartSurface` | 趋势与统计图 | 画布内联或地平线层，统一筛选、图例、tooltip、空态和展开入口 |
| `StatusBadge` | 运行、通信和设备状态 | 图标 + 文字 + 语义色 |
| `DataScopeLabel` | `Plant` / 设备名标签 | 明确哪些模块不随作用域变化 |
| `ContextRail` | 告警、日志和工单 | 画布边缘的连续上下文，不为每条信息再造卡片 |
| `ActivityRow` | 告警与日志 | 统一时间、设备、级别、摘要和关联入口 |
