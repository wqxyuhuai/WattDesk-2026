# Service Ticket 页面说明

更新：2026-10-30

状态：**P0 本地交互预览已实现**。`/service` 提供卡片列表，`/service/:ticketId` 可直接打开和刷新。筛选、搜索、新建、编辑、回复、提及、附件本地预览和状态切换均在当前会话内真实执行；仍未接入后端、登录权限、上传、持久化或通知服务。

## 1. 目标

Service Ticket 是面向客户的售后服务工单模块，用来提交设备或电站问题、反馈和需求，并与售后团队及其他有电站访问权限的用户持续沟通。

核心约束：

- 每张工单必须关联一个电站。
- 工单只有 `Ongoing`、`Closed` 两种状态。
- 工单完成后由作者或有服务权限的人员手动改为 `Closed`，不自动关闭。
- 能查看关联电站的用户才能查看该工单。
- 作者、售后和有电站访问权限的用户可以在工单内回复。
- 发帖和回复都可以添加图片和附件。
- 回复楼中回复时，被回复的楼层作者会收到提示；工单作者也应收到该工单的新回复提示。
- 当前未接后端、登录或权限。真实可见性、持久化、上传和通知必须等接口接入后实现，前端不能假装已经完成。

## 2. 推荐设计方向

### 2.1 列表页

最终方向采用**等高卡片网格**，与 Plants 的表格列表形成明确区分，同时不照搬参考图中的瀑布流或 Kanban。

- 工单具有标题、正文摘要、作者和最后活动，天然适合卡片承载。
- 卡片使用统一尺寸和信息槽位，不使用高低错落的 masonry。
- `Ongoing` 与 `Closed` 混合排列，在卡片右上角显示状态，不增加分组标题；当前状态只由明确的关闭/重开操作改变。
- 卡片是普通数据表面，不使用玻璃；默认无描边、无重投影，也不绘制静态点阵。玻璃仍只用于按钮、菜单和浮层。
- 卡片整体可点击进入详情。桌面指针 hover 时显示共享 PixelCard 适配器的低透明度像素与光标微光；默认和离开后不保留纹理，键盘 focus 使用真实焦点环操作。

推荐列表结构：

- 当前页为单级 `Service ticket` 面包屑，不渲染独立的大标题；右侧 `New ticket` 使用与 Plants `New plant` 相同的共享 `wd-page-action` 轻量文字动作，默认透明，hover / focus 才显示浅灰胶囊。
- 页头通过共享 `createPageHeader({breadcrumb})` 与 Plants 完全一致，不复制尺寸或位置；列表当前页为单级 `Service ticket` 面包屑，不单独渲染页面标题。
- 工具栏从左到右为状态筛选、约 30px 高的竖分隔线、`All / Mentioned me / Created by me` 胶囊；搜索放在右侧。
- 所有状态混排为一个卡片网格。
- 桌面端使用一行 3–4 张等高卡片，收窄后自动降为 2 张、1 张；不通过横向滚动查看卡片。
- 每张卡片在左上显示胶囊票号、右上显示状态；中部为标题与两行摘要，摘要后有一条左右通开的分隔线，线下方左侧为作者、右侧为最后活动。移除电站、附件数、回复数和提及标记。卡片必须保持平面、无默认描边和重投影，通过表面明度与间距建立层级。

### 2.2 详情页

采用 Linear Windows app 的核心结构，而不是复制其视觉皮肤：

- 左侧是正文、讨论、回复区和发帖入口，是主要阅读路径。
- 右侧是粘性属性栏，放状态、关联电站、作者、创建时间、最后活动等工单属性。
- 桌面端采用“主内容 + 属性栏”两列；窄屏时属性栏移到正文上方或收起，页面整体不产生横向滚动。
- 正文与回复使用普通数据表面和分隔线，不把每张回复做成玻璃卡。玻璃只用于按钮、菜单和浮层。

### 2.3 讨论结构

参考 GitHub Discussions、Discourse 等讨论产品的常见模式：

- 工单正文是楼主帖。
- 正文下方显示按时间组成的回复流。
- 默认按时间正序，最新回复在底部；提供日期排序按钮切换到最新优先。
- 只保留一层楼中楼。回复“回复”时继续显示在同一讨论组，并用 `Replying to @name` 保留上下文，不继续无限缩进。
- 每个楼层通过卡片底部常驻回复入口进行回复；自己的楼层额外通过三点菜单提供编辑和删除。
- 当前用户使用 `You` 标签，工单作者使用 `POSTER` 标签；两个标签可以同时出现。
- `POSTER` 使用共享 `Accents/Brown` 64% 与 `Grays/Black` 36% 混合出的深琥珀实底，禁止恢复亮黄底；`YOU` 使用共享蓝色 `Accents/Blue` 实底。两者文字在深浅主题下固定为白色，POSTER 白字对比度至少 `4.5:1`。徽标继续沿用 `Caption2/Regular` 的 `10px / 12px` 行盒与 15px 胶囊高度。
- 共享头像按直径统一缩写字号：22–24px 为 `9px / 10px`，25–32px 为 `11px / 13px`，33px+ 为 14px。列表卡片的 24px 作者头像与 Properties 的 22px 作者头像都使用 compact 档；头像尺寸、描边与共享 `.wd-avatar-label` 的 `0.5px` 视觉居中不变。28px 评论头像继续使用 11/13，36px 账户头像不受影响。
- `New ticket` 在新工作区标签打开 `/service/new`，原列表保留；新页直接进入工单详情同构编辑态并聚焦标题。编辑已有工单、新建回复、编辑回复仍在最终展示位置原位进入编辑态，不使用弹窗。

这样既有论坛的连续讨论感，也不会因为无限嵌套在窄屏和长工单里失去可读性。

### 2.4 可替代形态与取舍

如果后续卡片被证明不适合真实数据量，可退回到统一的讨论列表；状态只作为行内属性，不恢复分组标题。Kanban 暂不推荐：只有两个状态，拖拽带来的业务价值有限，还会让长标题和附件难以阅读。

## 3. 范围划分

### P0：首次可用界面

- Service Ticket 列表与详情两类页面。
- 状态 `Ongoing / Closed` 的展示和本地筛选。
- 工单关联电站展示，以及创建时必选电站。
- 搜索、状态筛选、范围筛选和排序。
- `Mentioned me` 筛选和 `@` 提及功能。
- 工单正文、附件展示和讨论列表。
- 回复、回复某楼、编辑/删除自己的回复。
- 卡片列表与混排等高卡片布局。
- 新建工单的新标签直接编辑页；已有工单和回复的原位编辑态。
- 发布工单和回复时的图片/附件选择、预览、移除和失败提示。
- 按权限显示关闭、重开、编辑、删除等操作。
- 深色、浅色、键盘操作、减少动态效果和窄屏适配。

### P1：需要真实后端后再启用

- 按电站权限的真实可见性。
- 真实附件上传、病毒扫描、下载权限和过期清理。

- 提及通知的已读、清除与顶栏入口。
- 服务角色、跨组织处理权限、审计日志。
- 服务端分页、全文搜索、附件容量配额和速率限制。
- 邮件通知、订阅、举报/审核等运营能力。

## 4. 信息架构与路由

建议在接入实现时扩展为：

| 页面 | 推荐 URL | 说明 |
|---|---|---|
| 工单列表 | `/service` | 固定入口，保留现有路径 |
| 工单详情 | `/service/:ticketId` | `ticketId` 使用稳定服务端 ID，不使用标题或数组下标 |
| 新建工单 | `/service/new` | 新标签打开，直接进入详情同构编辑；发布后当前标签切换为稳定详情 URL |

新建工单规则：

- `New ticket` 通过新工作区标签打开 `/service/new`，不修改原列表标签。
- 新页面复用详情双栏：左列承载标题、正文、附件与右对齐的 Cancel / Publish 操作，右列 Properties 与标题顶部对齐并展示 Status / Plant / Author / Created / Last activity / Replies；打开后标题自动聚焦。Plant 在 Properties 内选择，不使用正文区原生选择器。
- 发布前要求标题、描述和关联电站完整；发布成功后当前新标签原地切换为 `/service/:ticketId` 详情，不再额外新建标签。
- Cancel 或面包屑返回会关闭当前新标签并回到来源列表；直接刷新 `/service/new` 会开始新的空白编辑，当前草稿不持久化。

工单展示编号与 URL ID 分开：

- URL 使用稳定 `ticketId`。
- 界面显示 `NO.25638663` 一类可读票号。
- 票号可以变化或后来才生成，不反向成为路由主键。
- 已发布工单详情的 Properties 将票号作为列表第一项：`Ticket ID` 标签在上，票号胶囊在下，再往下依次是其他属性。票号与列表卡片共用 `.service-card-number` 的字体、填充和圆角，仅将属性栏内高度调整为 `20px`、水平内距调整为 `7px`。新建草稿在发布前不显示虚假票号。

列表打开详情时，推荐沿用 Plants 的语义：新建并激活详情标签，原列表标签保留，便于比较多个工单。详情页使用共享页头中的 `Service ticket > NO.25638663` 面包屑返回：

1. 优先激活打开详情时记录的来源列表标签；
2. 关闭当前详情标签；
3. 直接刷新进入且没有来源标签时，在当前标签内回到 `/service`。

这组交互已用于当前本地预览。

## 5. 可见性与权限

### 5.1 可见范围

- 工单与电站是一对一必填关系，不允许无电站工单。
- 创建时只列出当前用户有权查看的电站。
- 查看工单的前端条件是该工单关联电站对当前用户可见；最终授权必须由服务端执行。
- 用户失去电站访问权限后，工单列表、详情、附件和通知都必须停止可见。
- 对无权访问的工单建议返回 `404 / Not found` 语义，避免通过 `403` 暴露工单是否存在。
- 售后人员能跨客户处理工单，但不能依赖前端绕过电站权限；需要明确的服务角色与授权规则。

### 5.2 建议能力位

前端不要硬编码角色名，由接口返回当前用户对工单的能力：

| 能力 | 建议规则 |
|---|---|
| `canView` | 有权查看关联电站 |
| `canReply` | 工单为 Ongoing，且当前用户可查看 |
| `canCreate` | 至少有一个可访问电站 |
| `canEditTicket` | 默认仅工单作者；服务人员是否可编辑正文待确认 |
| `canDeleteTicket` | 默认仅工单作者，且删除前二次确认 |
| `canClose` | 工单作者或服务角色 |
| `canReopen` | 工单作者或服务角色 |
| `canEditComment` | 当前楼层作者 |
| `canDeleteComment` | 当前楼层作者 |

真实业务上线后，按钮隐藏只改善体验，不能代替服务端授权。

## 6. 工单状态与生命周期

状态固定只有：

- `Ongoing`：可以回复，显示绿色状态点和文字。
- `Closed`：服务处理完成，默认只读；显示中性状态，不使用高饱和背景。

建议流转：

```text
Ongoing --作者或服务人员手动关闭--> Closed
Closed  --作者或服务人员重开------> Ongoing
```

待确认的推荐默认值：

- 不自动关闭、不根据长时间无回复自动改变状态。
- `Closed` 后暂停新回复；需要继续沟通时先 `Reopen`。
- 关闭与重开都显示确认操作，并在成功后保留作者、时间和状态变化记录。
- 状态变化应写入讨论时间线，但不伪装成普通用户回复。

## 7. 列表页

### 7.1 标题区

- 当前页：`Service ticket` 面包屑当前项
- 说明可选，默认不堆叠说明文字。
- 右侧动作：`New ticket`，使用共享 `createPageHeaderAction()` / `.wd-page-action`：28px 高、左右 10px 内距、6px 图文间距、14px 图标、13px / 510；默认透明且无玻璃，hover / focus 才显示浅灰胶囊。不得恢复为 36px 中性玻璃按钮。
- 页头布局、标题位置、右侧动作对齐与分隔线复用 Plants 页面，不复制新结构。
- 共享页头固定 `40px` 高，页面顶部空档为 `4px`；面包屑和右侧主按钮必须垂直同轴居中。详情面包屑与列表页头高度一致，单级和两级目录均使用 14px / 510。

### 7.2 状态与筛选

范围筛选使用单行胶囊，视觉参考 Linear `My issues` 的分段 pill，但改用项目现有 token：

- `All`
- `Mentioned me`
- `Created by me`

范围筛选是互斥条件，默认 `All`。三个 pill 固定 `36px` 高，与左侧 `All status` 完全一致。默认 pill 使用更淡的 `Fills/Quaternary`；选中 pill 使用稍亮的 `Fills/Primary`、主文字色和 1px `Labels/Quaternary` 内描边，默认/选中必须明确可区分；hover / focus 恢复主文字色。不新增彩色胶囊体系。三个按钮挂共享 `.wd-press-scale`：hover / 键盘 focus 按玻璃控件的 `1.025` 基准轻抬，按下到 `1.065`，释放按 `420ms` 共享弹性回落，按钮尺寸和排版槽位不变。

状态条件：

- `All status`
- `Ongoing`
- `Closed`

`Mentioned me` 不能通过前端搜索正文里的 `@` 文本猜测，必须读取服务端生成的提及记录。用户必须已拥有关联电站访问权限，才能被提及、搜索到或收到通知。

组合规则：

- 状态、范围、搜索之间为 AND。
- `Mentioned me` 与 `Created by me` 互斥，不能同时选中。
- 搜索应在服务端权限范围内匹配票号、标题、正文和电站名。
- 任何筛选都不能返回用户无权查看的电站工单。

### 7.3 排序

推荐：

- `Last activity`：默认，最近回复或状态变化在前。
- `Newest first`
- `Oldest first`

### 7.4 卡片结构

已发布卡片使用统一的信息槽位：

| 信息 | 说明 |
|---|---|
| 状态 | 右上角显示绿点 + `Ongoing`，或中性 `Closed` |
| 票号 | 左上角胶囊显示服务端可读编号，如 `NO.25638663`；使用等宽编码字体 |
| 标题与摘要 | 标题最多两行；摘要一行，不显示裸露 HTML |
| 作者 | 共享头像 + 名称 |
| 最后活动 | 卡片右下显示最后回复或状态变更时间，并与左下作者垂直中心对齐；7 天内使用共享相对时间，之后显示本地 `YYYY/MM/DD HH:mm`，完整时间放 title 和无障碍文本 |

不显示截图中意义不明的眼睛/浏览数，除非后续产品明确其含义并接入真实数据。

卡片不使用封面图、附件缩略图或状态分组标题。标题与摘要之后设 1px `Separators/Non-opaque` 分隔线并横向贯通卡片内容边缘，线下只保留作者与时间；状态位于右上角。不显示电站、附件数、回复数或 Mentioned 标记，减少信息密度。

卡片 hover 由 `components/pixel-card.js` 提供非 React 的 PixelCard 适配层，使用间距 `5px`、像素 `1px`、速度 `35`、从指针位置 `600ms` 展开、`spotlight .72 / glow .58 / opacity .48 / fade .35`。深色点阵使用白色 `#ffffff / #ffffff / #f8fafc`；浅色点阵使用共享 `Labels/Secondary` 深色 ink，确保整卡及底部都清晰可辨。FlipCard glare 与编号胶囊扫光继续使用白色光效。不启用默认 intro；canvas 默认不可见，只有 hover 绘制，离开后淡出并清空，减少动态效果时直接显示或清除。点径、间距、展开时长与清理逻辑保持不变。

同一卡片由 `components/flip-card.js` 提供 FlipCard 的原生交互适配：`tiltMax 12`、`glareOpacity .22`、`hoverScale 1.03`、`perspective 1100`、`stiffness 170`、`damping 20`。指针移动产生轻微 3D 倾斜和跟随反光；浅色主题使用白色径向渐变与 `screen` 混合，深色主题沿用主文字色光效。hover 最多放大到 `1.03`；拖动超过 `4px` 会加入有限阻尼倾斜，释放后回弹并抑制 click，因此不会误触跳转。卡片点击仍保持“打开工单”，不使用会改变该动作的 flip-on-click；默认无描边、无投影和静态反光，hover 背景高亮和阴影暂时关闭。`prefers-reduced-motion` 下关闭倾斜、放大和反光。

列表滚动视口在左侧向页面内侧留出约 `16px`、顶部留出约 `18px` 的透明绘制空间，使 hover 时的 1.03 缩放不被滚动宿主裁掉；可见卡片左缘、网格右缘、`New ticket` 右缘与滚动轨道位置不变。顶部和底部越界回弹面使用共享滚动反馈的透明默认值，直接露出母面板，不能出现独立白色或实底横条；回弹距离、内容位移与滑块反馈继续由共享滚动组件负责。阴影 token 暂时不应用，后续若重新启用必须重新验收深浅主题与边缘裁切。

每次指针进入卡片，编号 `.service-card-number` 的伪元素播放一次 `680ms` 斜向扫光，从胶囊左上移到右下，使用 `--wd-motion-sheen` / `--wd-ease-sheen`。动画只播放一轮，结束保持透明；指针离开后移除状态，下一次 hover 可重新播放。文本、编号底色和胶囊尺寸不变，减少动态效果时由共享媒体查询关闭。

已发布卡片默认等高；标题、摘要和元数据使用固定行数与最小高度。新建/编辑草稿是唯一允许临时增高的卡片状态，提交后回到统一卡片高度。

当前 184px 卡片内部的垂直分配为：标题上距 `18px`，摘要到贯通分隔线约 `17px`，分隔线到 Footer `10px`，Footer 到卡片底缘 `16px`。调整时要保持卡片总高不变，优先把底部区收紧出的空间留给标题和正文，不重新压缩阅读区。

### 7.5 空态

- 没有任何工单：`No service tickets yet`，仅对有创建权限的用户显示 `New ticket`。
- 搜索或筛选无结果：说明可调整搜索或清除筛选，提供 `Clear filters`。
- 用户没有任何可访问电站：提示需要先获得电站访问权限，不显示可点击但注定失败的创建按钮。

### 7.6 加载、刷新和分页

- 首次真实等待超过共享 `140ms` 阈值时才显示骨架。
- 列表刷新不清空当前搜索，除非用户明确点击 `Clear filters`。
- 大量数据使用服务端分页；设计预览阶段可用本地样例，但不能宣称已接服务端分页。

## 8. 工单详情

### 8.1 页面骨架

桌面端从左到右：

1. 共享页面顶栏中的 `Service ticket > NO.25638663` 面包屑，与列表标题区固定同为 40px 高；统一使用 14px / 510，分隔复用顶栏 `asset-14.svg` 前进箭头，颜色与父级同为 Labels/Secondary。箭头首帧直接使用 `masks/asset-14.svg` 不透明面具，刷新时不得先出现暗色再变浅。路径列表不再追加 `gap`，父级链接右内距与当前项左内距各为 8px，使箭头左右视觉间距相同。非当前目录可点击，hover / focus 显示两端半圆的浅灰胶囊底，不使用文字下划线。
2. 主内容栏：标题、楼主帖、附件、讨论、回复输入区。
3. 属性栏：状态、电站、带头像的作者、创建时间、最后活动、回复数；背景与一级讨论卡一致，顶部与工单标题对齐，并按标题顶部初始偏移固定，不随讨论区滚动。

属性栏顶部与工单标题顶部对齐；两列都要适配 `1545×1252` 与 `1920×1080`。不使用首页绝对坐标 scene。

Properties 的吸顶位置由标题顶部相对详情滚动视口的实际距离计算，包含当前 `scrollTop` 修正，因此从滚动第一像素起就固定；不能使用固定 `top:32px` 让它先随内容移动再吸附。窄屏取消 sticky 时清除该动态值。桌面工单操作入口位于标题同一行右侧，右缘与主内容列对齐，不留在页面级页头。

### 8.2 主内容

标题区：

- 工单标题使用共享 `Title3/Emphasized`，保持紧凑但不厚重。
- 工单编号使用 `Footnote/Regular`，不与标题抢层级。
- 标题与正文之间不使用独立卡片底色，正文直接铺在页面内容区。

楼主帖：

- 正文使用 `Subheadline/Regular`（15px / 400），保留换行和长链接换行。
- 图片按原始比例缩放，限制最大显示高度；点击后才能进入完整预览。
- 非图片附件以短文件名标签显示；列表中不展示大小，完整下载能力由后续接口提供。
- 楼主可在权限允许时编辑或删除自己的工单；`Edit ticket` 不让页面跳到表单，而是把同一正文区原位切换为编辑态。
- 编辑态中的标题、正文、电站和附件占位与阅读态一致；`Save` 成功后原位置恢复阅读态，取消后恢复原值。

### 8.3 属性栏

建议属性：

| 属性 | 交互 |
|---|---|
| Status | 显示当前状态；有权限时点击打开共享 `.wd-menu`，执行关闭或重开 |
| Plant | 显示关联电站；是否允许跳转 `/plants/:id` 待电站详情完成后决定 |

| Created | 使用全站共享时间规则：7 天内相对时间，之后显示本地 `YYYY/MM/DD HH:mm` |

属性栏普通字段不是按钮，不能因为 hover 缩放；只有真正可操作的状态行使用共享控件反馈。

### 8.4 更多菜单

楼主和管理能力放到工单标题行右侧的 36px 中性玻璃圆钮，右缘与主内容列对齐。显示 `asset-70.svg` 三点省略号图标，图标为 18px 且与圆钮中心完全重合，`aria-label` 为 `Ticket actions`：

- `Edit ticket`
- `Delete ticket`
- `Close ticket / Reopen ticket`，也可只保留在属性栏，避免重复入口

菜单必须复用共享菜单浮层、Glass Surface、行高和勾选槽规则；不能另造一套页面菜单。菜单不显示可见标题，只以 `aria-label="Ticket actions"` 保留无障碍名称，并由共享 `mountMenu()` 自动使用 `.wd-menu--no-heading` 的上下各 `10px` 内距。

## 9. 回复与讨论

### 9.1 楼层

每条顶层回复包含：

- 头像、作者、`POSTER` / `You` 标签、回复目标、时间。
- 回复正文和附件。
- 楼层底部常驻回复入口；不再在楼层头部显示独立 `Reply` 按钮。
- 自己的楼层在 hover / 键盘 focus 时显示 36px 三点玻璃圆钮，菜单仅包含编辑和删除。

有权限时，自己的回复三点操作入口在 hover / 键盘 focus 时渐显；触摸设备不能依赖 hover，需要始终有可见入口。操作容器使用共享 `.wd-hover-reveal-host` / `.wd-hover-reveal`，透明度进入 `240ms`、离开 `360ms`，不能只依赖内部按钮自身的 hover transition。点击圆钮使用共享菜单浮层显示 `Edit` / `Delete`，编辑原位切换，删除使用确认弹窗，指针离开且菜单关闭后圆钮渐隐。

无需标题的 `Edit / Delete` 菜单由共享 `mountMenu()` 自动添加 `.wd-menu--no-heading`，顶部、左右和底部内距均为 `10px`，不得在页面局部另写菜单内距。

正文与评论区之间固定一条通栏分隔线，分割线上方留白 `84px`，下方到常驻回复框留白 `40px`。随后从上到下依次为：常驻新回复编辑器、Activity 标题与排序按钮、一级讨论卡列表。每张一级讨论卡底部都有 `Reply to this thread…` 回复框；点击后在该卡内部展开最终楼层样式的编辑态，并显示 `Replying to @name`，不打开新弹窗。排序按钮显示复用 `asset-14.svg` 的向下箭头，排序文字底部与 Activity 标题底部对齐，文字、箭头与 hover 背景的中心线一致，文字与箭头间距为 `6px`。

### 9.2 楼中楼

- 只允许一层视觉嵌套：顶层回复及其直接回复组成一个讨论组。
- 每个顶层回复是一张简洁讨论卡；所有二级回复放在这张卡内部，并用水平分隔线区分，不各自堆叠卡片。
- 对子回复再次回复时，不增加第三层缩进；显示新的直接回复并标注 `Replying to @name`。
- 可以直接回复楼主帖，也可点击某楼层 `Reply`。
- 点击 `Replying to @name` 能定位到父楼层；父楼层被删除时保留不可点击的已删除上下文。
- 不把整段父楼层复制成永久引用，避免正文重复和过期内容误导。

### 9.3 排序

- 默认 `Oldest first`，最新回复位于底部。
- 点击排序切换为 `Newest first`，最新回复位于最上。
- 排序作用于一级讨论组，组内直接回复仍按时间正序，保证上下文自然。
- `Oldest first / Newest first`、向下箭头与 hover 背景共用同一垂直中心线；文字位置保持与 Activity 标题底部对齐，只调整按钮盒与箭头中心。
- 用户正在阅读历史内容时收到新回复，不强制抢滚动；显示 `1 new reply` 提示，点击后定位。

### 9.4 编辑和删除

- 只允许作者编辑或删除自己的回复。
- 编辑回复时，该楼层原位切换为编辑态；头像、作者、楼层位置、正文宽度和附件区保持不变。
- 编辑后显示 `Edited` 状态；完整编辑历史是否公开待后端审计规则确认。
- 删除有子回复的楼层时，不连带删除他人回复；父楼层显示删除占位，子回复保留上下文。
- 工单删除属于高风险操作，必须二次确认；是否软删除和审计保留待后端规则确认。

## 10. 原位发帖与回复编辑器

新建与编辑只维护两套共享展示组件：

- `TicketContent`：工单标题、正文、电站、附件和动作区；支持 `read / edit / create` 状态。
- `ReplyRow`：回复头像、作者、正文、附件和动作区；支持 `read / edit / create` 状态。

`read` 与编辑态不能各自维护一套独立样式。字段只替换文字区域，不改变卡片/楼层的字体语义、内距、头像、附件区和动作区位置。

### 10.1 新建工单

- 点击 `New ticket` 时，在新工作区标签打开 `/service/new`，原列表标签保留；不插入草稿卡。
- 新页面使用与详情一致的“左编辑区 + 右 Properties”双栏。左列标题、正文和附件右缘对齐，Cancel / Publish 按钮组右缘与同一内容列一致；右列 Properties 与标题顶部对齐。
- `Plant` 必填，放在 Properties 的 Plant 行；点击后打开 288px 浮窗，沿用 Plants 公司筛选二级浮窗的 `wd-filter-menu` 内胆、玻璃搜索框、32px 行、选中标记与共享滚动反馈。支持按电站名称或 SN 搜索，单选后在 Properties 回显名称。
- `Title`、`Description` 必填；`Attachments` 可选。
- 初始状态固定为 `Ongoing`，不在卡片内提供状态选择。
- 主按钮 `Publish ticket`，次按钮 `Cancel`；每个草稿卡只保留一个主按钮。

### 10.2 编辑工单

- 从工单详情 `More` 菜单选择 `Edit ticket`，原正文区原位切换为编辑态。
- 编辑态保持展示态的标题与正文排版，不显示输入框边框或焦点矩形。正文从单行起步，随内容自动增高，禁止拖拽手柄和内部滚动。
- 不显示文字型 `Add image or file`、`Mention`、上传说明或工具条；附件使用与评论输入一致的 36px 回形针圆钮，与 Cancel / Save 同一操作行。正文输入 `@` 仍可打开人员选择器。
- 进入编辑态时标题行不移动，标题自动聚焦且光标位于文本末尾；聚焦使用 `preventScroll`，不能带动详情整体下沉。附件、Cancel、Save 三个按钮左到右按共享 stagger 原位渐显，任何关键帧都不能带位移；Activity 分隔线与讨论卡使用 FLIP 从原位置平滑向下接住新增高度。
- 标题编辑使用单行语义的自动增高 `textarea`，短标题保持 `25px` 行盒；超过 `760px` 内容宽后自然换行并向下生长，不能横向裁切或出现内部滚动。Enter 不插入换行，粘贴中的换行归一为空格。展示标题使用相同宽度上限、字体、行高和 `overflow-wrap:anywhere`，保存或发布前后换行一致。
- 标题、正文、附件三层必须保持展示态原坐标：标题 25px 行盒 + 11px 间距，正文 block 显示，附件区顶部距正文底部 16px。附件 chip 不能因 textarea 的 inline 基线或外边距合并发生上下跳动。
- 保存或取消时反向执行同一套动效：按钮从右到左原位渐隐，Activity 内容回到展示态原坐标后再重绘。标题和正文在退出过程中保持不透明，不能先淡出成空白；使用共享 panel、hover 与 stagger token，减少动态效果时直接切换。
- 工单编辑态只影响标题、正文和附件区域；Activity、全部一级讨论卡和 `Reply to this thread…` 必须保持可见且可操作。允许工单编辑器与楼内回复编辑器同时展开，`Esc` 或回复 Cancel 只关闭回复编辑器，不得退出工单编辑。
- 已发布工单如更改关联电站，会改变可见人群；推荐发布后锁定电站，除非用户确认允许服务人员迁移。
- `Save` 成功后保持当前详情和滚动位置，不重新加载整页。

### 10.3 新建与编辑回复

- 发起新一级回复的 `ReplyRow` 固定在 Activity 标题上方；不放在长讨论列表末尾，避免评论较多时找不到。
- 顶部评论框在 Ongoing 工单中始终展示，并使用独立的 `commentDraft`。打开楼内回复、编辑回复或切换排序时都不能隐藏它或丢失已输入内容；它与讨论列表之间至少保留 `16px` 间距。
- 独立新回复编辑器不再重复显示姓名标题行。桌面空态高度约 `100px`，内距为 `14px / 16px`，正文使用无四边框的 `contenteditable` 文本盒，单行起步并随内容纵向增长至 `180px`；右下只保留 `36px` 中性玻璃回形针和发送圆钮。占位文字在卡片 hover 或 focus 时转为主文字色，进入 / 离开使用共享 `240 / 360ms`。
- 一级讨论卡内的 `Leave a reply…` 内联编辑器，hover / focus 只提升占位文字到主文字色；左侧 28px 当前用户头像的填充、缩写颜色、描边和阴影保持静止。
- 两类回复框的自动增高统一调用 `animateContentHeight()`，使用 `--wd-motion-content-grow` / `--wd-ease-content-grow`（当前 `280ms`）。连续输入会取消上一轮高度动画并从当前可见高度继续；首次渲染和减少动态效果不做生长动画。
- 顶部评论框、全部一级回复卡和右侧 Properties 共用 `wd-discussion-card` 表面。深色主题保留 1px `Separators/Non-opaque` 内描边、贴边高浓度且外侧快速衰减的零位移双层阴影；浅色主题下三者统一使用纯白 `Backgrounds/Primary` 背景，并移除内描边和全部外侧投影。三者继续共用 `18px` 连续曲率圆角，由共享 `geometry.js` 识别并应用 `superellipse(1.2)`，不能退回普通 `round`。
- 输入框的占位文字和编辑文字绑定 `Subheadline/Regular`，明确使用 SF Pro、15px / 400 / 20px / -0.23px，与讨论卡正文一致。Enter 创建段落，Shift + Enter 创建段内换行；相邻段落额外增加 `6px` 上距，因此段间距大于 20px 行距。发送后的正文使用相同的段落间距。
- 输入超过 `180px` 后，独立回复框和楼内编辑器都通过 `.service-reply-input-host` 调用共享 `createScrollFeedback({elastic:false})`：原生滚动条隐藏，右侧显示共享 `10px` 轨道与 `6px` 圆角滑块。滚轮位于输入框内时优先滚动文本，到达上下边界后才释放给外层页面；输入文本滚动时上方固定回复框不发生位移。
- 回复输入的滚动滑块颜色显式映射全局 `--wd-figma-labels-tertiary` / `--wd-figma-labels-secondary`，不继承内容区为提高正文可读性而加深的 Labels 值；默认和 hover 颜色必须与详情页主滚动条一致。
- 粘贴始终按纯文本处理：优先读取 `text/plain` 并重建普通段落 / `<br>`，不允许带入来源颜色、字体、字重、字号、链接或布局；只有纯文本为空时才从 `text/html` 降级提取文字。
- 浅色主题下正文与属性文字必须清晰可读：仅 `.service-board`、`.service-empty`、`.service-detail-content` 内把 Secondary 设为约 70% 主文字黑、Tertiary 设为约 55% 主文字黑，正文与属性等关键文字对比度至少 4.5:1。`Reply to this thread…` 默认提示更淡，使用约 45% 主文字黑，hover / focus 转为主文字黑。该覆盖不得作用于页头、工具栏或共享搜索框，不能修改全局 label token 或深色主题。
- 所有回复发送圆钮共用 `home-assets/service-ticket/send-up.svg` 的 16px 向上箭头，不再旋转导航箭头；图形在 16px 盒内以 1.6px 圆头笔画居中，按钮本体仍为 36px 玻璃圆钮。
- 正文和附件都为空时，发送圆钮使用中性禁用态；出现正文或附件后，发送切换为共享蓝色主按钮。附件与发送均复用标准玻璃圆钮，不自写背景、阴影或按压反馈。
- 一级讨论卡内的编辑器复用同一输入与动作纹理，只显示 `28px` 当前用户头像和透明内容列。头像、回复占位文字与上方评论头像、正文共用同一左缘，不增加高亮面板。
- 楼内 `Reply to this thread…` 的占位文字和编辑文字都使用 `Subheadline/Regular`。收起态与编辑态均为 `49px` 高，外距 `8px`、上下内距 `10px`，头像实际上下留白为 `11px / 10px`，文字与头像保持同一视觉中心；承载回复入口的卡片不使用额外底部内距。两个操作按钮相对整行绝对居中并渐显，不参与行高，只有正文换行后才自适应。
- 本人回复进入原位编辑时，附件与发送之间增加 36px 中性玻璃 X 圆钮，X 图标盒为 10px、无障碍名称为 `Cancel`；点击后丢弃当前编辑草稿并恢复原回复。取消与发布图标的笔画厚度接近，新建回复不显示 Cancel，三枚按钮始终同一垂直中心。
- 进入编辑态后，段内文字行盒仍做约 `1px` 的既有光学校正，避免字体基线读起来下沉；段落容器、头像、行高和操作按钮位置不变。
- 本人一级回复进入原位编辑时，作者行固定为 `36px`，展示正文和单行编辑器共用 `20px` 行盒；卡片顶边、作者行、正文起点、底部分隔线与回复入口都不移动。只有输入实际换行后才按内容增高。
- `POSTER` / `YOU` 标签保留 `Caption2/Regular` 字族与字重，文字使用 `10px / 12px` 行盒，外层胶囊高度保持 `15px`，不能比回复正文更抢眼。
- 点击一级讨论卡底部常驻回复入口后，在该卡内部展开复用同一结构的 `ReplyRow`，不新增楼层头部的 `Reply` 按钮。
- 编辑自己的回复时，原楼层切换为同一个 `ReplyRow` 编辑态，不新增第二块卡片。
- 编辑时保留原楼层的作者、角色徽标、时间和卡片底部回复入口；只有正文位置切换为输入编辑器，卡片不得收缩或隐藏回复信息。
- 空内容且没有附件时不能提交。
- 上传中阻止重复提交，但允许用户取消或重试失败的上传。
- 成功后把回复插入正确位置并保持焦点/播报结果；不伪造实时刷新。

### 10.4 提及

- 输入 `@` 打开人员选择器，只显示对当前关联电站有访问权限的用户。
- 选择后在正文中显示结构化人员标签，提交时同时发送 `mentionUserIds`；服务端保存明确的提及关系。
- 被提及用户出现在 `Mentioned me` 筛选并收到通知。
- 提及不会授予电站权限；无权用户不能通过猜测名称被提及或搜到。

### 10.5 文本能力

P0 推荐纯文本：

- 保留换行。
- 自动识别普通 URL，但必须安全渲染。
- 不实现 Markdown/富文本工具栏，直到产品确认格式语法和内容安全策略。

### 10.6 附件

- 图片和普通文件都要有上传中、成功、失败、移除四种状态。
- 图片在正文中显示预览；其他附件显示短文件名，界面不显示文件大小。
- 所有上传都由后端返回 ID 和经过权限校验的 URL，前端不把本地预览 URL 当成已上传成功。
- 文件数量、单文件大小和 MIME 白名单由后端策略返回，不在页面文档里猜测固定值。
- 错误提示要具体到文件，例如类型不支持、超出大小或上传失败，不使用“操作失败”笼统提示。

## 11. 通知

### 11.1 事件

至少定义：

| 事件 | 接收人 |
|---|---|
| 有人直接回复工单 | 工单作者 |
| 有人回复某一楼层 | 该楼层作者 |
| 有人回复楼中楼中的某条回复 | 被回复回复的作者 |
| 有人在工单或回复中提及用户 | 被提及用户 |
| 工单状态被关闭或重开 | 工单作者，以及需要跟进的服务人员 |

建议：

- 同一事件中若工单作者同时也是被回复楼层作者，只生成一条通知。
- 不给自己发通知。
- 通知链接打开具体工单和回复锚点。
- 接收人失去电站权限后，历史通知不再显示正文摘要，也不能通过链接重新获得内容。

### 11.2 与现有顶栏关系

当前顶栏通知按钮的旧浮层已被用户要求移除，仍在等待重做。本页面不得恢复旧通知浮层，也不得在页面内另造第二套通知中心。

因此通知需要拆成独立依赖：

1. 后端事件与已读数据；
2. 顶栏通知入口重做；
3. 工单详情和回复锚点路由；
4. 权限回收后的通知清理/脱敏。

在通知中心重做前，页面最多可以显示真实的工单内 `Unread replies` 数据；没有真实数据时不显示假红点或假 toast。

## 16. 验收清单

### 路由与工作区

- `/service` 刷新仍在列表。
- `/service/:ticketId` 直接打开和刷新仍显示同一工单。
- `New ticket` 必须在原列表标签之外新建 `/service/new` 标签；不能继续插入列表草稿卡或打开弹窗。
- 列表打开详情、返回来源列表、浏览器前进/后退与标签 URL 一致。
- 未知工单显示 `Ticket not found`，不静默回 Home。

### 产品逻辑

- 创建时不能缺少电站。
- 状态只有 Ongoing / Closed，且只由明确操作改变。
- 卡片混合展示 Ongoing / Closed，状态筛选项的结果基于当前数据真实计算。
- `Mentioned me` 读取真实提及关系，不能误用正文包含 `@` 代替。
- 新建工单使用详情同构的新标签编辑页；已有工单编辑和回复新建 / 编辑在原位完成，提交前后沿用同一组件。
- 无权限电站的工单不会出现在列表、详情或附件请求中。
- 回复和附件都以服务端成功结果为准。
- 楼中楼只保留一层视觉缩进，回复目标和排序正确。
- 关闭后行为与重开权限符合最终确认规则。

### 视觉与交互

- 深浅主题下正文、次级文字、分隔线和状态色清晰可辨。共享页头在 Plants、Service Ticket 列表和详情中均为 40px 高，面包屑与右侧按钮中心线一致；所有面包屑层级为 14px / 510，分隔图标来自 `asset-14.svg`、颜色与父级一致且左右各留 8px 视觉间距，首帧不会出现透明度过渡中间态。父级 hover 背景圆角为 6px 且无下划线。Properties 与一级回复卡背景一致、顶部与工单标题对齐，滚动详情时保持同一屏幕位置；浅色主题下顶部独立回复编辑器、一级回复卡和 Properties 的背景均为纯白，`box-shadow` 均为 `none`，18px 连续曲率仍保留。工单操作圆钮在标题行内、与主内容列右缘对齐，三点图标水平和垂直中心均与 36px 圆钮重合。范围按钮具备共享 hover / press 缩放。
- 卡片网格不出现瀑布式错落；已发布卡片在相同断点下等高，正文与页边距保留足够留白。卡片默认无描边和无投影，hover 不改变底色、也不加阴影，只增加像素纹理、3D 倾斜、跟随反光和编号单次扫光；默认 canvas、glare 与扫光必须完全不可见，离开后不得残留点阵、倾斜或循环动画。范围按钮默认与选中填充必须有清晰明度差。拖动不得误开工单，普通点击仍进入详情。网格右缘与 `New ticket` 右缘对齐，滚动轨道使用共享组件并位于右侧空隙。
- 所有按钮、菜单、输入、头像、滚动条复用共享组件。
- 超长回复输入的共享轨道可见且可拖动；原生滚动条不可见；滚轮先改变编辑器 `scrollTop`，外层详情滚动位置在文本仍可滚动时保持不变。
- hover / focus / 选中 / 禁用 / 加载状态完整。
- 页面没有整页横向滚动；1545×1252 与 1920×1080 均可用。
- 窄屏属性栏不与正文重叠，回复与附件操作不依赖鼠标 hover。
- 键盘可访问排序、回复、附件移除、状态菜单和返回入口。
- `prefers-reduced-motion` 不阻塞内容或操作。

### 通知

- 通知事件去重，不给自己发通知。
- 通知只能由有权用户看到。
- 失权后通知摘要和深层链接都不泄露工单内容。

## 17. 审核时需确认的决策

当前预览已采用以下推荐默认值；进入真实后端阶段前仍需业务确认：

1. **Closed 后默认只读**：继续沟通前需要作者或服务人员先重开。推荐保留该规则，避免已关闭工单继续沉淀未跟进内容。
2. **关联电站发布后不可更换**：发布前可改；发布后更换电站会同时改变可见人群，推荐锁定，只有服务权限可做受审计的迁移。
3. **列表打开详情使用新工作区标签**：与 Plants 一致，原列表保留。若希望论坛式单标签浏览，可改为当前标签内进入。
4. **详情左正文、右属性栏**：属性栏在桌面端粘性，窄屏折叠到正文顶部。是否允许用户手动收起属性栏可在实现时再定。
5. **回复采用一层楼中楼**：不是完全平铺，也不是无限树。
6. **P0 文本为纯文本**：保留换行和链接，不支持 Markdown/富文本。若需要专业引用和代码块，应单独定义编辑器与安全规则。
7. **Service 角色与关闭权限需业务确认**：谁属于售后、能否跨客户关闭或重开、是否允许编辑他人正文，必须由后端权限模型给出。
8. **附件限制由后端策略返回**：需要产品确认允许类型、单文件上限、单帖数量和存储周期。
9. **通知渠道**：当前先定义站内通知事件；是否需要邮件、桌面通知或每日摘要尚未确认。顶栏通知中心是独立前置任务。
